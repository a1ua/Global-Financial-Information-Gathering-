1. 目标、默认决策与交付边界

首版服务个人研究者，以 A 股盘前、盘后研究为主，收集国内政策、宏观、公司公告及影响 A 股的隔夜美股信息。全球信息是观察范围，首版不承诺覆盖全球全部市场。

系统回答四个问题：发生了什么、证据是什么、影响假设是什么、判断形成后的结果如何。核心交付物是带证据的简报、版本化事件与判断库、可重复计算的结果核对报告。

决策 本版默认 调整条件
使用方式 本地 CLI + 静态 HTML + Markdown 归档 有明确查询需求后增加界面
主要市场 A 股；美股作为隔夜信息输入 双市场采集与日历稳定后增加美股独立简报
来源范围 首批 3–5 个经验证来源，覆盖国内官方信息、海外官方信息、资讯补充 验收通过后逐类扩源，不以数量代替覆盖质量
标的范围 固定指数与少量可获得稳定数据的行业代理；自选池为可选配置 自选池未配置时不阻塞公共简报
行情 优先验证免费、允许使用且字段完整的日线来源 无合格来源时单列采购或范围调整，不伪造替代数据
模型 一个支持结构化输出的云端 Provider，薄封装 凭证与限额配置完成后才启用真实调用
推送 本地文件与状态页 邮件、企业消息等外发渠道后续单独接入
复盘 先做描述性结果核对与市场调整收益 样本充分后再研究市场模型、因子调整及统计检验

首版不包含交易执行、目标价、仓位建议、逐笔行情、用户体系、向量数据库、知识图谱、自动调参或源权重自动学习。个股公告可作为证据输入；个股收益评价需满足证券主数据与行情质量条件后启用。

3. 总体架构与运行任务流

采用独立 CLI 命令，由 Windows 任务计划程序启动；同类作业加锁，SQLite 写入通过事务串行提交。无需常驻服务即可完成首版。每个任务具有可持久化状态与幂等键，失败可从最后一个已提交步骤恢复。

来源注册与验证
    ↓
独立轮询 → 抓取/限速/重试 → 原始内容与获取日志落档
    ↓                           ↓
标准化与精确去重             源健康/缺失/延迟记录
    ↓
结构化抽取 → 字段校验 → 证据绑定 → 事件版本与多源关联
    ↓
候选聚类 → 规则裁决 → 必要时模型裁决 → 冲突保留
    ↓
重要性筛选 → 影响假设/弃权 → 判断及评价协议冻结
    ↓
按报告信息截点选择输入 → 引用检查 → 模板渲染 → 原子发布/归档

独立行情任务 → 行情质量检查 → 行情版本与交易日历
                                  ↓
冻结判断 + 已成熟窗口 + 固定行情快照 → 确定性核对 → 周报
                                  ↓
人工评审改进建议 → 新配置/提示词版本 → 回归验证后用于未来记录

状态统一为 queued、running、succeeded、degraded、failed；评价样本另有 pending、eligible、evaluated、unavailable、excluded。失败必须记录原因码，不能静默跳过后将整次运行标为成功。

环节 成功路径 失败/恢复路径
抓取 解析后持久化条目，再推进检查点 单源隔离，限次退避重试；失败不推进检查点
增量发现 游标结合重叠回看窗口，内容哈希幂等 同时间戳、乱序发布、正文修订均有回归用例

报告生成 临时文件完成校验后原子发布 保留上一份成功版本；失败版本不覆盖正式文件

电脑离线 启动时检查漏跑区间并补采 超出源可回溯范围时记录不可补齐区间，不声明完整

4. 调度、时间与数据就绪规则

作业 初始调度 前置条件与边界
collect 按源分档轮询，初始候选 15–30 分钟 实际频率由限速、价值与源更新节奏确定；不统一承诺 60 分钟
market-sync 目标市场收盘后按供应商实际延迟抓取 开收盘、假期及提前收市来自版本化交易日历
brief-pre A 股交易日北京时间 08:30 固定本次信息截点；隔夜行情显示实际日期与就绪状态
brief-post A 股交易日北京时间 16:30 行情未齐可先出降级版，后续补版使用新版本号
review 每日检查成熟样本；周末汇总 观察窗口已结束且所需行情完整；未成熟不评分
maintenance 每日检查、定期备份 空间、数据库完整性、来源健康、预算和备份结果

时间规范：UTC 为存储与比较基准；另外保留来源原始时间文本、时区、精度及解析状态。A 股显示 Asia/Shanghai，海外事件按来源所在地时区解析。发布时间只有日期时不可补出具体小时；该类记录不进入精确发布延迟统计。

区分 published_at（来源声称发布）、first_seen_at（系统首次观察）、collected_at（本次获取）、created_at（判断生成）。复盘使用历史事件对应日期的时区规则，不能用今天是否夏令时推断历史。

本地运行的持续服务能力取决于电脑开机、联网及休眠设置。验收记录实际可运行时间；电脑离线仍计入面向用户的运行缺口，不通过剔除时段美化稳定性。

5. 数据源验证与接入门槛

首批来源按类别选少量代表：国内政策/监管、海外宏观/监管、补充资讯；行情与交易日历作为独立依赖验证。具体机构和供应商保留为候选，不能在验证前标记“可用”。

每个 source 配置至少包含 source_id、类别、入口、采集方式、来源分级、轮询间隔、限速、时区、解析器版本、存储策略、重叠回看范围、可回溯范围和备选来源。

接入检查必须覆盖：列表与正文样本、分页/增量、空结果、修改或撤回、时间解析、重复发布、限速和错误响应。保存测试日期、真实样本与失败原因。公开可访问不自动代表允许全文存档，按来源条件确定全文快照或摘要/链接/元数据存档策略。

首批行情门槛：标的代码稳定，开收盘字段和交易日期明确，复权/分红口径可解释，缺失可识别，历史区间满足拟评价窗口。主来源未通过时，简报 MVP 可继续，但定量评价保持关闭。

6. 数据契约与版本规则

对象 核心字段/关系 约束
sources / source_runs 来源配置版本、运行时间、HTTP状态、错误码、延迟 配置历史可追踪，运行状态单独维护
raw_items source_id、原始URL、获取时间、发布原文、内容哈希、存档位置、存档策略 内容修订保存新版本；允许存储的证据只追加
events event_id、version、事实摘要、类别、市场、实体、supersedes 来源文本与事实事件分开；修订追加版本
event_evidence event_version、raw_item_id、证据片段定位、支持/转述/冲突 一个事件可关联多个来源；不得仅以URL存在判定支持
event_clusters 聚类版本、成员事件版本、合并理由 标题相似不等于同一事件；后续进展与原事件关联
predictions 生成时间、输入版本清单、目标、基准、方向、理由、反证、评价协议、model/prompt/config版本 append-only；更正追加并引用被替代记录
instruments / calendars 标准代码、交易所、币种、基准映射、交易会话、日历版本 标的与基准同一评价币种；跨币种换算另建协议
market_bars 标准代码、session_date、OHLC、币种、来源、调整口径、获取时间、数据版本 修订保留版本；不覆盖已引用快照
review_results prediction_id、行情快照、协议/算法版本、结果、状态、排除原因 同输入版本计算一致；重算新增结果版本
report_runs / llm_calls / job_runs 输入清单、截点、输出哈希、调用状态、token、费用、任务状态 报告与模型输出留档；凭证与敏感配置不写入日志

判断方向使用 positive、negative、neutral、mixed、uncertain；另存 direction_basis，明确预测绝对收益还是相对基准收益。标准化目标必须是代码，不能仅存“半导体”之类自由文本。

拆分 extraction_quality（抽取检查结果）与 judgment_confidence（模型自评等级）。首版用低/中/高等标签，明确它未经概率校准，不可解释为命中概率。

不可变性由应用限制、唯一键及数据库拒绝 UPDATE/DELETE 的触发器共同实现；这是防误修改措施，不宣称防止数据库文件所有者篡改。修订、补版与迁移必须有显式流程及备份。

7. 模型任务、证据约束与预算

逻辑职责 实现方式 输出与失败策略
抽取分类 模型结构化输出，规则校验 原文没有的字段留空；无证据事实拒收或退回
去重聚类 URL规范化、内容哈希、标题/实体/时间候选优先 只有歧义候选调用模型；误合并可通过新聚类版本纠正
影响假设 对重要且证据足够事件调用模型 增量、影响链、适用范围、反证、方向与弃权原因
简报表达 结构化事实/解释/观察事项；模板渲染 引用有效性由代码检查，证据支持度另做抽检
周报解释 只读取确定性计算完成的汇总表 不让模型计算收益、补齐价格或声称已证明因果

来源正文一律作为不可信数据：正文内指令不能改变系统规则、调用工具或访问本机资源。模型不承担自主浏览、行情获取或任务调度。

保存实际模型标识、提示词版本、参数、输入哈希和原始输出。低随机性参数仅在接口支持时设置，不作为确定性保证。缓存键包含内容、模型、提示词、规则及输出模式版本。

预算字段包括每日金额/token上限、单次输入上限、单次输出上限、最大重试数和最大候选事件数。Phase 0 填入实际数值；未设置限额时不启用批量真实调用。调用前预估并预留预算，超限进入降级流程。费用无法即时确定时显示估算值及依据，不伪装为结算值。

8. 结果核对：先冻结协议，再观察结果

8.1 分开两类研究

事件反应观察以首次公开时间定位，描述事件附近的市场变化；系统判断评价以判断形成后冻结的起点定位，检验后续结果。两者分别展示，不能混算命中率。

历史回放仅用于验证代码、数据对齐与流程。今天的模型可能已知历史结果，即使遮蔽未来行情，也不视为无污染的前瞻证据。系统有效性主要依靠上线后追加的前瞻记录。

8.2 首版评价协议

  1. 判断写入时固定：证据版本、目标代码、基准、绝对/相对方向、生成时间、起止规则、阈值、收益口径、协议版本。
  2. 主协议统一采用判断生成后、且开盘时间严格晚于生成时间的下一交易会话开盘作为起点。首版窗口为该会话至第1个/第5个交易会话收盘，名称明确为“下一会话开盘→第N会话收盘”。
  3. 主协议要求目标与基准具有同一会话的可靠开盘、收盘数据。不满足时记 unavailable；不得悄悄改用昨收。仅收盘数据可另设协议，起点为生成后首个会话收盘、终点为其后第N个会话收盘，单独汇总。
  4. 目标与基准均用相同起止时点、相同收益口径。第一段计算开盘至收盘收益，其后为收盘至收盘收益；涉及拆股、分红等公司行动且无法保证口径一致时暂停该样本评分。
  5. 定义每段 AR = 目标收益 − 基准收益；CAR = 各段 AR 之和。另可展示持有期复合收益差，但必须单独命名，不能混用。
  6. 相对方向按 CAR 判定；绝对方向按目标持有期收益判定。正负阈值按目标类型在验证前固定，不能看结果后调整。neutral、mixed、uncertain 单独报告，不并入二元命中率。
  7. 窗口结束且行情完整才评分。停牌、缺失、公司行动异常、重叠事件分别标记；排除规则预先定义，并展示被排除样本数量和原因。

简单减基准收益属于市场调整方法，不等于估计并剥离标的 beta。首版只描述关联表现，不把超额收益直接归因于某条新闻。市场模型与多因子调整作为后续独立研究阶段。

8.3 汇总与可复现

每次报告给出记录总数、有效方向样本数、成熟数、弃权率、数据完整率、命中率、CAR分布及重叠事件标记。首版优先少量粗分组；建议有效独立事件少于30时只展示样本，不作稳定性结论，达到30也不自动代表统计充分。

同一事件的多个标的或窗口不能当成独立事件扩大样本量。置信区间与显著性分析后续加入时，需处理事件依赖、重叠窗口及多重比较。首版不自动优化参数或源权重。

固定输入快照、行情版本、配置与算法版本时，结构化计算结果一致；报告生成时间等元数据不纳入数值一致性比较。LLM重新调用另存版本，不承诺逐字重现。

9. 技术方案与目录

Python 3.11+；httpx、feedparser、BeautifulSoup用于HTTP/RSS/HTML；pydantic用于契约；SQLite与允许保留的原始文件用于存储；Jinja2负责HTML；pytest验证关键边界。数值计算使用现有简单实现或pandas，按实际需求引入。依赖与行情供应商在Phase 0锁定版本。

外部依赖包括多类信息源、行情源、交易日历、模型服务与网络，不能简化为“1库1API”。FTS5如需启用先验证本机SQLite支持；全文搜索不阻塞首份简报。

每项任务默认由同一开发者执行；“可并行”表示依赖允许，不代表已经配置多人。工期不按并行人力压缩。

11. 评测设计与Definition of Done

先建立带来源、时间、类别、证据片段及重复关系的标注集。50条样本用于冒烟检查；建议另冻结不少于100条、覆盖各主要类型与中英文的验证集。开发集和验证集分离，样本数量是初始规划，不代表统计充分。

指标/检查 本版门槛或规则 验收证据
事件覆盖 限定来源、主题与观察区间，独立人工标注关键事件；目标≥80% 标注清单、分母、漏采原因与区间
延迟 分别报告发布→发现、发现→入库、入库→报告；不可靠发布时间单列 按来源P50/P90及机器离线情况；M0锁定可实现SLO
去重 精确重复幂等100%；语义候选合并精确率目标≥95%，召回率单列 重复对标注、误合并与漏合并列表
分类 冻结验证集总体准确率目标≥90%，主要类别单列 数据集版本、混淆情况与错误样本
证据引用 输出事实100%有可解析引用；抽检无重大无依据事实 引用检查结果与人工支持度抽检记录
时间与收益 假期、盘前/中/后、DST、提前收市、未成熟窗口、缺失数据用例通过 固定测试与手算样例
不可变与复现 拒绝普通历史改写；同快照同版本数值一致 触发器测试、输入清单与结果对比
降级恢复 断网、单源失败、模型失败/超限、行情缺失、任务冲突均可解释 故障注入记录与恢复后状态
连续运行 至少7个交易日，报告完整/降级/失败/迟到均计数；无未解决阻断故障 运行日志、缺口清单与验收结论
备份维护 备份包含数据库及所引用证据；演练副本恢复成功 恢复记录、操作手册、版本与配置说明

重大无依据事实包括虚构数字、把转述当官方决定、错误主体或日期。发现后阻止该内容发布或生成明确降级版；“样本抽检未发现”不能写成全量无幻觉保证。

标准RSS/API的新源配置接入可追求10分钟完成，但首次接入验证、复杂页面解析和来源许可检查不包含在该目标内。

12. 风险、阻塞与范围调整

风险 触发信号 处理与交付影响
来源不可用或无法保存必要证据 样本失败、字段不稳定、存储条件不允许 替换或缩小覆盖；不能用未验证源凑数量
行情/日历不合格 缺开盘价、时区不清、复权无法解释 保留简报MVP，关闭相应评价；在M0后重估
机器离线或任务重叠 漏跑、锁冲突、采集积压 补采与幂等恢复；记录不可恢复缺口
模型错误或预算耗尽 输出校验失败、无证据事实、达到限额 事件清单降级，不输出未经校验的影响判断
样本稀疏及历史污染 分组过细、回溯表现显著优于前瞻 减少分组，展示样本，停止有效性结论
数据供应商修订 同日期价格或正文变化 新增版本；旧结果不静默变化
范围增加 新市场、推送、个性化、自动调参进入首版 独立记录新增工作量与验收，避免挤占基础可靠性

13. 交付清单与首周执行顺序

交付包包含：可安装运行的项目、版本锁定依赖、配置样例、无密钥的环境说明、来源验证报告、带引用的示例简报、评价协议、示例核对报告、测试结果、运行验收记录、备份恢复手册及已知限制。

首周顺序：先完成范围与来源实测；再打通一条来源到事件库的链路并同步验证行情；随后完成证据绑定与静态简报；最后接入任务计划程序，开始持续运行观察。任何阶段先产出可检查样例，再扩大来源或功能。

首版通过后才考虑：美股独立简报、自选池增强、检索界面、市场模型、置信度校准与提示词实验。多源冲突保留、证据支持和运行恢复属于首版基础能力，不后移。
