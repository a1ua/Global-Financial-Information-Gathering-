# 全球市场信息 Agent：立项章程 V3

日期：2026-11-07｜基线：[开发计划 V2.0](../market-intel-agent-dev-plan-v2-20261107.md)｜状态：待真实数据与前瞻运行验证

本章程补齐 V2 的立项价值、覆盖边界和阶段决策条件。数据契约、时间口径、评价协议与运行架构沿用 V2；本文件不代表已完成连通性测试、系统开发或运行验收。

## 1. 立项假设与用户价值基线

目标用户为单个 A 股研究者。核心假设是：在固定、可说明的来源范围内，把证据归档、增量筛选和简报整理自动化，能够减少日常阅读时间，同时不增加重大事实错误或关键事件遗漏。

“前瞻判断是否存在稳定统计表现”是独立研究问题，不作为简报软件交付前提。首版的软件价值由研究耗时、事实可靠性、覆盖完整性和持续运行能力共同衡量。

在首个试运行交易日前冻结基线方法：由使用者按同一来源矩阵完成至少 3 个交易日的人工阅读记录；随后至少 7 个交易日使用系统，并保留必要原文核查时间。样本仅用于产品决策，不作统计充分性承诺。

| 项目 | 记录方法 | 立项观察目标 |
| --- | --- | --- |
| 每日研究耗时 | 盘前、盘后分别记录实际阅读与核查分钟数，不含等待程序时间；人工基线和系统辅助期使用相同覆盖范围 | 系统辅助期中位耗时比人工基线减少至少 30%；若未达到则分析整理、核查或内容排序的成本，不直接扩源 |
| 关键事件遗漏 | 人工独立标注覆盖范围内的关键事件，记录系统是否在报告截点前发现并纳入 | 达到冻结的覆盖门槛，同时逐条解释漏采与漏选原因 |
| 可用观察事项 | 使用者为简报中的观察事项标记“可直接使用 / 需修改 / 无用”，保留修改理由 | 至少一半可直接使用；此目标为产品试验门槛，不等于投资有效性 |
| 事实可靠性 | 对已发布内容检查来源支持、数字、主体、日期和转述性质 | 无未解决的重大无依据事实；发现后回退相关输出并追踪修复 |

用户无法持续提供耗时和使用反馈时，仍可交付技术 MVP，但立项结论必须写为“用户价值未验证”，不能替换为模型自评。

## 2. 首版范围与覆盖矩阵

“全球”描述信息视角，不代表全面覆盖。每个来源必须通过实测后写入实际机构、入口、覆盖主题、回溯范围及失效条件。以下为待填实的范围基线，不是已接通清单。

| 观察类别 | 首版承诺 | 首版明确缺口 | 扩展触发条件 |
| --- | --- | --- | --- |
| 国内政策与监管 | 至少 1 个经验证官方来源；围绕利率、监管及配置的重点政策主题 | 未接入机构、地方政策及非公开信息不纳入覆盖承诺 | 运行稳定且漏采清单证明扩源有明确收益 |
| 海外宏观与监管 | 至少 1 个经验证官方来源；观察影响 A 股的海外事件 | 不承诺覆盖全部经济数据或全球监管活动 | 已有数据完整、时区明确，新增主题可独立验收 |
| 补充资讯 | 最多先接入 1 个可用补充源，明确标注转述与核实状态 | 不将媒体报道等同于官方确认，不承诺全网舆情 | 事实核查负担可接受且不降低证据质量 |
| 公司公告 | 先支持已接入来源内、与观察实体相关的公告证据 | 不承诺全 A 股公告无遗漏；个股评价默认不启用 | 主数据、证券映射与行情质量通过后单列范围 |
| 行情与基准 | 固定指数及少量行业代理，代码和数据口径在 M0 冻结 | 不包含逐笔、全市场资金流或任意自选股收益评价 | 行情与公司行动处理能满足已冻结协议 |
| 交易日历 | A 股运行日历；海外来源时间转换及必要会话信息 | 美股独立盘前/盘后简报不属于首版 | 双市场调度、提前收市及数据延迟实测通过 |

每份简报展示本次实际覆盖的来源、信息截点及不可用来源。缺少输入时标记降级；不以旧数据、模型常识或不相干主题填补。

## 3. 事件重要性与筛选规则

首版使用可审阅的规则排序，不让模型单独控制样本入口。重要性和方向判断分开保存。

规则优先级依次为：官方决定或公告、冻结的重点事件类型、命中观察实体、首次出现或实质修订、发布时间。来源级别是证据质量线索，不保证经济重要性；已确认的关键事件采用显式规则保留，不能仅因标题不含关键词而丢弃。

具体执行要求：

1. 精确去重后保存所有合格条目；筛选只影响报告和模型调用，不删除原始事件。
2. 为每条入选、未入选、仅列标题或送模型的记录保存规则版本、命中项与原因码。
3. 每日报告长度和模型候选上限在 M0 冻结；超过上限保留完整事件索引，并标记被截断区间。
4. 实质修订、撤回或多源冲突优先进入人工核查/显式提示，不能自动归并为已确认事实。
5. 对漏选样本单独统计。修改规则形成新版本，不回写历史判断或将旧表现当作新规则前瞻表现。

## 4. 指标、分母与验收口径

开发集、验证集和前瞻运行期分别保存，不混算。人工标注由开发者初标、独立审核 Agent 检查一致性，争议事项由使用者或明确授权的负责人裁定。审核 Agent 不得直接修改门槛以使结果达标。

| 指标 | 分子 / 分母或计算口径 | 初始目标与限制 |
| --- | --- | --- |
| 关键事件捕获率 | 截点前已入库的人工关键事件数 / 冻结来源、主题和区间内人工独立标注的关键事件总数 | ≥80%；分母不能仅来自系统已采集内容；超出覆盖范围另列 |
| 关键事件报告覆盖率 | 截点前已在报告中出现的人工关键事件数 / 同区间人工关键事件总数 | 单独报告，区分抓取漏采与规则漏选；不得与捕获率混用 |
| 分类准确率 | 分类正确的验证记录数 / 冻结验证记录总数 | ≥90%；按类别及中英文分列，缺失输出计错误 |
| 合并精确率 | 被系统合并且人工确认同一事件的候选对数 / 系统实际合并的候选对总数 | ≥95%；无合并对时记不可计算，不报100% |
| 合并召回率 | 被正确合并的真实重复候选对数 / 标注集真实重复候选对总数 | 分别报告，不以低合并率掩盖漏合并；分母为零记不可计算 |
| 引用可解析率 | 引用可解析且对应实际输入证据的事实陈述数 / 已发布事实陈述总数 | 100%；仅链接存在不等于事实受支持 |
| 事实支持度 | 人工抽检确认受证据支持的事实陈述数 / 本次抽检事实陈述总数 | 报告样本数、抽样方法与错误明细；重大错误为发布阻断项 |
| 简报按时率 | 目标时间内发布的完整或明确降级报告数 / 观察期计划报告总数 | 完整版、降级版另列；机器离线仍在分母，迟到不算按时 |
| 完整报告率 | 截点及必需输入满足要求的完整报告数 / 观察期计划报告总数 | 不把降级报告算完整；门槛由 M0 实测锁定 |
| 发布/处理延迟 | 按可靠发布时间→发现、发现→入库、入库→报告分别算 P50/P90 | 时间仅精确到日期或无法解析的记录单列；不得强行补时间 |
| 评价数据完整率 | 到期且所需价格完整的评价样本数 / 观察期所有到期评价样本数 | 显示缺失、停牌及异常原因；不把缺失收益记零 |
| 弃权率 | uncertain或明确弃权判断数 / 已进入判断阶段的事件数 | 同时展示未进入判断阶段数量及筛除原因，避免筛选隐藏样本 |
| 二元方向命中率 | 达到预先冻结规则的正确正/负判断数 / 已成熟且数据完整的有效正/负判断数 | neutral、mixed、uncertain单列；正负方向和绝对/相对口径不可混算 |

覆盖与时效的 SLO 在 M0 根据来源特性冻结。连续运行验收至少 7 个交易日，附完整/降级/失败/迟到计数，且无未解决阻断故障；该观察长度不证明长期可靠性或研究有效性。

## 5. 阶段退出与停止条件

| 阶段 | 退出条件 | 不满足时处理 |
| --- | --- | --- |
| M0 范围与依赖验证 | 覆盖矩阵填实；至少两个官方来源有真实样本；运行环境可用；预算与依赖明确 | 缩小范围或替换来源；无法获得合法且足够的证据则暂停相关能力，不进入扩源开发 |
| M1 简报 MVP | 一条真实来源纵向链路可运行；引用和原始证据可回溯；重跑幂等；失败可降级；无模型仍能输出事件清单 | 修复数据与证据基础，暂停增加模型能力、主题及界面 |
| M2 可评价版本 | 固定判断协议；行情/日历合格；无未来数据用例、手算和固定快照重算通过 | 保留简报功能，关闭不合格评价；不得以备用口径静默替换 |
| M3 运行交付 | 至少7个交易日记录；恢复演练通过；无未解决阻断缺陷；交付文档与限制齐全 | 修复后重验受影响窗口；不把技术完成写成运行验收完成 |
| 价值复核 | 人工基线与使用期记录完整，耗时、遗漏和事实可靠性可以比较 | 数据不足标为未验证；连续试用无明显节时或核查负担过高，优先调整范围和排序，不继续加功能 |

任一阶段发现严重无依据事实、评价前视偏差、历史判断可被普通操作改写、无法解释的行情口径变化，应暂停相应输出或评分直至修复。暂停范围以受影响能力为限，保留可验证的事件清单与证据访问。

## 6. 投入、缓冲与多 Agent 协作原则

V2的10–15个开发工作日作为原始参考。V3详细工作包汇总为90–147个有效投入小时（含WorkBuddy独立辅助），约11–19个单人等效工作日，作为当前总量预算；另预留2–3个工作日风险缓冲处理真实来源适配、环境差异或接口修订。至少7个交易日运行观察单列，可部分重叠。实际日历工期取决于可并行任务和主控集成能力，M0后重新估算，不把前瞻样本成熟期压入开发承诺。

多 Agent 用于并行检查和边界清晰的工作包，不假定必然缩短工期。接口协商、集成、审查和返工需要时间；不因 Agent 数量增加按比例缩短估计。

主控负责接口与共享 schema、依赖文件及集成；采集 Agent 负责来源与标准化；报告 Agent 负责模型输出与模板；独立验证 Agent 负责跨模块审查。WorkBuddy 作为能力待实测的额外执行端，先承担一个可隔离工作包或只读评审，不假定存在 CLI、API、后台协作或跨 Agent 消息接口。

每项委派包括任务 ID、允许编辑路径、输入版本、输出文件、验收命令、实际测试结果和限制。共享工作区遵守目录独占；涉及共享契约的变更由主控串行集成。验收未通过的依赖不得作为已完成输入。具体工作包、任务状态和 WorkBuddy 接入记录由主控维护的实施计划承接。

## 7. 本次立项决策

可以继续实施最小纵向链路及真实来源验证；暂不扩大到美股独立简报、全市场公告或自动调参。M0 决定数据可行性，M1 证明证据与简报链路可用，M3 结合运行记录与价值基线决定是否扩展。软件可用与研究有效性分别给结论。
