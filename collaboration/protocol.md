# 多Agent与WorkBuddy执行协议

## 调度框架

主控维护依赖图与任务板，选择依赖已验收的planned任务，授予明确文件写入范围并更新dispatched/in_progress；执行者产出文件、测试与交接，进入review；独立审查者复核，主控串行集成并更新done。失败保持证据，修复后重新审查。最多主控加3个Codex子Agent并发；WorkBuddy作为额外执行端，同样遵守单文件所有者。

开发框架由任务板、契约、目录所有权、任务单和验收闸门组成；不引入运行时LangGraph/CrewAI等依赖。若后续确需软件化调度，须以当前手工协作瓶颈为依据另行立项。

## 文件所有权

| 执行者 | 允许范围 | 公共变更处理 |
| --- | --- | --- |
| 主控/集成 | AGENTS、README、配置、共享模型、schema、CLI、总计划 | 唯一集成者 |
| 采集Agent | 明确指定的adapters/pipeline和对应测试 | 提交契约变更建议，主控整合 |
| 数据/复盘Agent | 明确指定的market/review和对应测试 | 不自行改变收益协议 |
| 模型/报告Agent | 明确指定的llm/report和对应测试 | 不改变截点与证据语义 |
| 独立审查者 | 审查报告或明确分配的测试文件 | 默认只读实现代码 |
| WorkBuddy | 当前任务单白名单；WB-01仅results目录 | 当前不修改共享代码 |

共享目录下不并发切换Git分支。首次基线提交并验证worktree能力前使用文件独占；以后需要隔离时，从相同已接受提交创建独立checkout，返回提交或patch，由主控逐一检查集成。未经确认不自动采用他人生成的安装脚本或运行代码。

## 任务交接格式

```text
任务ID / 目标 / 基线版本
依赖与允许读取路径
允许写入路径 / 禁止修改路径
输入样例与契约版本
具体步骤与不在范围内事项
交付文件及验收命令
实际结果与证据路径
未执行检查 / 阻塞 / 已知限制
状态及下一接收者
```

## 集成闸门

- G0 环境：解释器、SQLite、时区、安装方式可验证。py启动器存在不代表Python可用。
- G1 契约：字段、版本、时点、错误码和样例冻结，变更经过影响分析。
- G2 离线纵向样例：证据→事件→截点简报→manifest；合成fixture有显著标签，禁止冒充真实抓取。
- G3 真实来源：实测、增量、修订、幂等、引用与降级均通过。
- G4 评价：提交后起点、手算样例、成熟窗口、修订快照与复现均通过。
- G5 交付：恢复演练、用户价值对照、至少7交易日完整运行记录。

原型通过部分测试不会自动接受整个工作包或闸门。禁止把规划中的测试命令填写成真实测试结果。
